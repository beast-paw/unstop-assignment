3. What are the differences between  Subject  ,  BehaviorSubject  ,  and  ReplaySubject in RxJS? 
ANS:  
Subject - No initial value, and doesn’t replay old values to new subscribers.
BehaviorSubject - Needs an initial value, and replays the latest value to new subscribers.
ReplaySubject - Replays old values to new subscribers, based on a buffer size or time window.

5.Can you explain how  subscribe()  and  async pipe  work  in Angular and which one you prefer for managing observables? 
Ans: 
subscribe() -  It is used to manually subscribe the data.When you call subscribe(), it starts receiving the values emitted by the Observable and triggers some logic when those values change.
async pipe - The async pipe is a approach to handling Observables in the Angular template. It subscribes automatically to an Observable and updates the view whenever the value changes.
Both the subscribe() method and async pipe have their own use cases: 
 - async pipe is perfect for template binding and handling Observable data directly in the view.
 - subscribe() is ideal when you need to manage side effects, perform additional logic, or access the emitted values programmatically in the component.

3. Server-Side Rendering (SSR) in Angular.

1. What is Server-Side Rendering (SSR) in Angular, and how does it differ from Client-Side Rendering (CSR)? 
Ans: 
Server-Side Rendering (SSR) is the process where the initial HTML content of a page is rendered on the server, rather than in the browser. The server sends the fully rendered HTML to the browser, and the browser then displays it to the user.
CSR - the browser loads a minimal HTML page and downloads JavaScript code that renders the content in the browser. When a user visits a page, the browser downloads the necessary JavaScript, which then takes over and dynamically renders the content

5. How does SSR handle dynamic data coming from APIs? 
Ans:
In Server-Side Rendering (SSR) with Angular, dynamic data from APIs is handled as follows:

Server-Side Fetching: On the server, API calls are made before rendering the HTML. The data is injected into the page, ensuring users receive fully rendered content with up-to-date information.

Resolvers: Used to fetch data before a route is activated. This ensures data is available before the component renders, improving SSR performance.

TransferState: Transfers data from the server to the client, so the client doesn't need to make duplicate API calls. Data fetched on the server is passed to the client via TransferState.

Client-Side Hydration: After the SSR page is loaded, Angular "hydrates" the page, and the client-side application takes over for further updates and interactions.

Caching: Implement caching strategies (server-side, browser, or CDN caching) to improve performance by reducing repeated API calls.

8.How does hydration work in SSR, and how does Angular reconcile server-rendered 
content with client-side JavaScript? 
ans:
How Hydration Works in Angular:
Server-Side Rendering:
  Angular Universal renders the app into static HTML on the server and sends it to the browser.
Client Bootstraps:
  Once the page loads, Angular's client-side bundle (JavaScript) is downloaded.
Hydration:
  Angular reuses the existing HTML instead of re-rendering it. It attaches event listeners and restores component state, making the page fully interactive.

How Angular Reconciles Server and Client:
  Angular compares the server-rendered DOM with what the client would generate.
  If they match, Angular hydrates the page without destroying the DOM.
  If there's a mismatch (e.g., dynamic data changed), Angular may re-render parts of the DOM.

7.   What are differential builds in Angular, and why are they useful? 
Ans: Differential builds in Angular refer to the process of creating multiple builds of an application for different target environments (modern and legacy browsers) to optimize performance.
They are useful in following ways: 
- Differential builds allow Angular to produce optimized bundles for modern and legacy browsers, improving performance for users with modern browsers while still supporting older ones.
- It reduces the bundle size for modern browsers, improving load times and user experience, while ensuring backward compatibility with older browsers like Internet Explorer 11.
